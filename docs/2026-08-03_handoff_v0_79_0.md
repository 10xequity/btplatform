## §3. What the review pass and this session's own bugs say

**v0.75.0 found six defects across the previous session's ten releases, four of them in code no test
touched** — including a manual bracket override that reverted itself within minutes in exactly the case
the owner asked for it, and bracket generation double-booking every court on a 16-team draw.

**The sharpest finding was about the CHANGELOG itself.** v0.74.0's entry claimed a stale comment "was
corrected". It was not — `git show` proves a *new* comment was added near the problem and mistaken for
the fix. **A document saying a thing was fixed is not evidence the thing was fixed; only the file is.**
Registered as **C9** in `docs/INDEX.md`, and now encoded as cadence in `CLAUDE.md` §1.1 per the owner's
own instruction: preflight every session, `grep` the one claim you are about to build on, let guards
catch the rest, and do a full review plus documentation audit *periodically* rather than every session.

**And this session's own code produced four more, all caught by tests rather than reading:**

1. **The KOTC solver would have invented scores.** Its solution cap made the games decided *early* in a
   depth-first search look unanimous when the search had simply never got round to contradicting them.
   Found by the negative control that runs the solver on an empty net. Nothing else caught it, and it is
   the most dangerous thing this session could have shipped: confident, plausible, fictional scorelines
   that rank people.
2. **The closed form was computed and then ignored** — margins derived, full space searched anyway.
   Same defect shape as a guard that is computed and never asserted on. 14.6 s → 150 ms.
3. **I asserted one player's total could finish a round.** It cannot — a total pins that player's side
   only. Now a test in its own right, because the intuition is appealing and wrong.
4. **I asserted two margin-two games make a round ambiguous.** Also wrong: a margin-two game has a
   minimum total of 40, so two totalling 80 can only be 40 + 40. Ambiguity is about whether the round
   total can be *split* more than one way.

Items 3 and 4 are worth their own note: **twice this session the test was wrong and the code was right.**
Both times the first instinct was to patch the code. The habit that caught it was deriving the property
independently — 4000 randomised rounds verifying the closed form before writing it, and then reading the
failure message instead of the assertion.
