## §3. The pattern this session kept finding

**Seven defects, all reporting clean, and all the same shape: the thing existed and the path to
reaching it did not.** The rail went dark on the page where a tournament is built. The test fixture
could not reach the feature it existed to test. Captain scoring was pool-only, so it died when the
desk was busiest. The QR code had never worked and announced it only on the screen where it was
needed. Five pages had accumulated stray `</main>` tags because each new page is sliced off an old
one. The cache-buster sweep had never covered `.js`. Pool membership was unwritable before a schedule
existed, which is backwards for a board that arranges teams beforehand.

**And four defects in code written this same session**, every one caught by a test rather than by
reading: a team named "Spike Lee's" broke the seed data; the QR generator polynomial was built
reversed; QR format bits were split 8+7 instead of 7+8; and the bracket trim would have dropped
fourteen teams from a 22-team division.

**Two of my own negative controls passed while proving nothing** — one corrupted parity the decoder
ignores, one corrupted a mode indicator that does not affect output, and a third only exercised
`drop` proposals so it could not have caught an applied `move_down`. **A negative control aimed at
the wrong region is indistinguishable from a working one.** That is the sharpest lesson of the
session and it is now in §7.

## §4. Owner answers of record — do NOT re-ask

Direct commit **authorized** · CHANGELOG: owner will not hand-edit · waiver system **closed** ·
SafeSport / M25 **dropped** · Twilio / A2P **frozen** · **TruVolley / VolleyballLife must never be
scraped** ("no drop true volley") · **12-on-4 rejected**, 12-on-5 stands · rotating pairs

New, 2026-08-03:
- **Pool play never offers fewer than 8 games.** "if we do 6 on 2, with 4 games, we would double the
  number of games to equal 8."
- **Pools aim for 6–11 teams, larger where possible.** Mostly a grass concern; indoors is limited by
  courts.
- **Rebalancing is propose-then-approve, never automatic.**
- **Top division holds at 8** — trim the 9th/10th when they have played 8+ games; a large overflow is
  a second bracket, not a mass drop.
- **A 22-team division becomes 8 / 8 / 6** when the trailing six are competitive; 8 / 4 / 2 when the
  bottom two are adrift, and those two drop to the lowest division.
- **QR codes are for sending a link by text or email**, not for scanning off a screen — so the link is
  primary and the QR is a fixed image.

   something similar when forming league games that night, especially with single players that are
   forming nets."* Single **players**, not teams — so the tile is a person and the zone is a net.
   `admin-pool-board.js` is the general case to adapt, but the model differs and it needs its own
