## §2. What shipped in v0.88.0 — the sandbox seeder, and the guard that could not see it

`WIPE_SQL` deleted `brackets` before the `matches` that carry `bracket_id`. **D1 enforces foreign
keys** and `D1.batch()` is one transaction, so the delete raised `FOREIGN KEY constraint failed`, the
whole 57-statement wipe-and-reseed rolled back, and `POST /api/admin/testdata/generate` answered
**500** — reproduced live as `failed_modules:["sandbox"]`.

**The rows that triggered it were written by `generate` itself.** Its last step draws Winter Jam's
bracket through the real generator, which creates the `brackets` row and the `matches.bracket_id`
values that block the next run. **Press #1 on an empty range succeeded; every press after it failed,
permanently.** `wipe` shares the list, so the button whose entire job is clearing a stuck seed was
stuck on the same statement — **the owner had no recovery path from the UI, and was right that the
module did not work.**

Two more instances of the same defect were latent behind it and are fixed rather than left to surface
one at a time: `pools` also preceded the `matches` carrying `pool_id`, and `divisions` preceded the
`teams`, `pools` and `brackets` carrying `division_id`. The delete list now also covers the
`tryout_*` and `kotc_*` tables, `waitlists`, `form_fields`, `space_bookings`, `staff_shifts`,
`notifications` and `profiles` — **all measured empty on live**, so a tester evaluating one player or
seating one net would have re-broken the reseed, and fixing it cost nothing today.

### Why 1258 tests stayed green — both causes were in the harness, not the code

1. **`sandbox_seed.test.mjs` presses generate ONCE, against an empty database.** The defect only
   exists on the **second** press. *The state that breaks a reseed is the state the previous reseed
   left behind* — and my own first reproduction made the identical mistake and passed clean until I
   inserted the bracket rows generate itself writes.
2. **`d1-memory.mjs` ran `PRAGMA foreign_keys = OFF`, with a comment claiming that matched "D1's
   default". It does not.** Real D1 enforces them. Measured: the same 57 statements pass with the
   pragma OFF and fail with it ON, against the same schema. **A harness more permissive than
   production on exactly the axis under test is not a weak guard, it is an absent one.**

`createD1(schema, { foreignKeys: true })` is now opt-in, off by default so narrow fixtures keep
working. `wipe_order.test.mjs` ships **two guards that share no mechanism**: a **mechanical** one that
reads the foreign-key graph from `sqlite_master` and proves the order is topologically valid, and a
**behavioural** one that presses the real route **twice** with foreign keys on, plus a
wipe-then-generate recovery test. Both carry negative controls that mutate the real input.
**Proved-it-fails-live:** reintroducing the real defect in `sandbox.js` reddened **4 of 8**, and the
file was restored **byte-identical**.

### Verified against live D1 after the deploy, not just in the harness

The route that returned 500 was pressed **twice in a row** against production and returned **200 ·
`replaced: true` · `bracket_ok: true`** both times. Live D1 confirms the range was genuinely
rewritten — test contacts' `created_at` moved to the moment of the press, 48 contacts, 6 events, 62
teams, 204 matches, 24 registrations, and the bracket redrawn with **7 games** by the real generator.
Two `testdata.generate` rows were added to `audit_log`. **The second press is the one that used to be
impossible.**

### Three rules this job earned

- **Hand-ordering a delete list is not a method.** I wrote the corrected order by hand and got
  `teams.pool_id` wrong. The mechanical check caught it before it shipped. A hand-checked list is
  correct only until the next migration adds a key.
- **The "only sweep the buster when the release touches `web/**`" rule contradicts the C6 guard for a
  worker-only release.** I called "no sweep needed"; the guard reddened and **was right** — it ties
  the buster to whatever `index.js` reports, unconditionally. Given §3's stale-cache finding, forcing
  a re-fetch is the desirable outcome. **The standing rule needs the worker-only case spelled out.**
- **A check must not share the permissiveness of the thing it checks.** This is the C14 lesson
  arriving at the engine layer rather than the corpus layer.
