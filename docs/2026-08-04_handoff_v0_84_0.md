## §0. Delivery

**Direct commit.** Preflight CLEAR → commit → push → `gh run watch`. Migrations via Cloudflare MCP
before the push, ledger row read back after.

**WRITE THE CHANGELOG ENTRY INTO THE RELEASE COMMIT.** Proven twice now (v0.83.0, v0.84.0): the entry
goes in before the push, CI's `record-changelog` step finds it present, its "Commit and push" step is
**skipped**, and **CI adds no commit at all**. A release is ONE push. The unfilled-stub failure mode
that `CLAUDE.md` blames for the v0.36–v0.51 decay is structurally gone — there is no stub to forget.

```bash
node worker/scripts/changelog-entry.mjs --version v0.85.0 --date YYYY-MM-DD --body-file entry.md
node worker/scripts/changelog-entry.mjs --check --version v0.85.0     # --version is REQUIRED
```

Operational notes that hold:

- **`--check` requires `--version`.** Bare `--check` exits 4 with a usage error that reads like a
  failure if you are skimming.
- **`gh run list --limit 1` can hand you the GitHub Pages run.** Use `--workflow=deploy-worker.yml`.
- **CI's version-parity step is the authority**, not a local `/api/health` probe.
- **Only sweep the cache buster in a release that touches `web/**`.** v0.84.0 did: 0.83.0 → 0.84.0,
  **371** occurrences, one value before and after — and for the first time that count **includes the
  repo root** (§3).
- A docs-only change gets **no version bump** and **no sweep**.

### The animation design, and why the obvious build would have been wrong

`render()` replaces `innerHTML` wholesale every 25 seconds, so every node is a new node on every
poll. A keyframe on `.lv-court` — the obvious build — would have replayed **every card's entrance on
every poll, forever**, on a display left running all afternoon. That is exactly the "no
enter-animation on high-frequency controls" rule in standards §5, and it would have shipped looking
like a delivered feature.

So the page **diffs each payload against the previous one and animates only the difference.** The
nodes are new; the knowledge of what changed lives in a `prev` snapshot, not in the DOM. A poll where
nothing changed animates nothing. *On this board, movement is information.*

| Trigger | Effect | Values |
|---|---|---|
| A final score lands | Pop on the score cell + decaying flash on the card | `--dur-pop`, `--ease-out` |
| A card new to the board | Scale-in from 0.97, never 0 | `--dur-pop`, `--ease-out` |
| The round advances | On-now cards stagger, 40ms apart, capped at 8 | `--dur-pop`, `--ease-out` |
| A team changes rank | The row travels to its new position (FLIP) | `--dur-modal`, `--ease-in-out` |
| A champion appears | One pop | `--dur-modal`, `--ease-out` |
| First paint | One stagger | as above |

Every value from `tokens.css`; none invented. The flash fades a **composited overlay's opacity**
rather than animating a background colour, because transform and opacity are the only two properties
that skip layout and paint. Gold appears there as a low-alpha **background**, never as text.

Two things recorded so nobody "fixes" them:

- **Exits deliberately do not animate.** A card leaving is destroyed by the `innerHTML` replacement.
  Animating it out means a keyed reconciler — a much larger rewrite of a page whose first duty is to
  never blank. Instant is the limit case of "exits faster than entrances".
- **Two durations exceed 300ms on purpose.** The 900ms flash and the colour settle are *decays*, not
  responses to a tap. The ≤300ms rule governs how fast the interface answers the user; nothing here
  is a user action. The movement inside each effect is 180ms or 240ms.

### Three payload fields that were built, tested, and uncalled

`degraded` and `degraded_note` shipped in **v0.77.0**; `current_round` in **v0.73.0**. **No page read
any of them.** `live_board.test.mjs` covered the API side thoroughly — including a negative control
proving the flag is not stuck on — and nothing asserted the page did anything with it. Failure class
1, hiding behind a well-tested server.

The consequence was not cosmetic: a board that lost its bracket read rendered an **empty** bracket,
which asserts *there is no bracket*. A wrong answer presented as a fact, on the one surface where
nobody is watching the logs. It now shows the server's own sentence in `.notice error`.

**A degraded board animates nothing**, and drops its snapshot rather than diffing against it. A
section emptied by a failed read looks exactly like a section that emptied, so motion would dress a
guess as a fact.

## §3. What this session's work says about the guards

**A guard whose own header claims it "scans the WIDEST set" was scanning one directory too few, and
had reported clean for ten releases.**

`404.html` ships from the **repo root** — GitHub Pages serves it for any missing path — and it
references `/btplatform/web/assets/tokens.css?v=…`. It sat at **`?v=0.74.0`** while all 369 busters
under `web/` read 0.83.0. `asset_versions.test.mjs` scans `web/*.html` and `web/assets/*.js`. The
stale file was one directory up, so the guard was never wrong about anything it looked at.

Nobody had narrowed it. **The file was simply never inside it** — and this is the third instance of
the same shape in three sessions:

| Instance | The guard | What it could not see |
|---|---|---|
| C10 (v0.81.0) | nothing at all | the harness schema, which every other guard stood on |
| standards §11 (v0.82.0) | `schema_gate.test.mjs` | migrations 0004–0007, at `db/` root |
| **this session** | `asset_versions.test.mjs` | `404.html`, at the repo root |

**A file's location is part of whether a guard can see it.** "The widest set" has to mean the widest
set that *ships*, not the widest directory somebody remembered to name. Registered as **C13**.

Applied to the new guard deliberately: `live_motion.test.mjs` does **not** ratchet motion-value drift
— that is C11's mistake, and a page can fail by using nothing at all. Its first assertion is that
every animation name resolves to a real `@keyframes`, because `animation: lv-popp 180ms` is valid CSS
that throws nothing, logs nothing, and **animates nothing**: the button bug expressed in CSS. It also
flags the reverse — keyframes defined and never referenced. And its header states plainly what it
cannot see: **whether the motion looks good.** Timing and feel are judged by eye, in slow motion, on
the real board.

Also fixed: this page's `prefers-reduced-motion` block covered `transition` only. Every effect added
in v0.84.0 is a keyframe animation, so that block would have let **all of them** straight through — a
reduced-motion guarantee that was already false for anything using `@keyframes`.
