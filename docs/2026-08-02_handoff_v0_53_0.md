*Retired rule (2026-08-02):* ONE ZIP per release mirroring repo folders; ZIP contents diff-verify
equal to the exact changed file set vs the previous release's tree; BOTH manifest ratchets
mandatory (1: ZIP listing == changed set · 2: previous tree + ZIP == build tree byte-equal).
Workflow files are the only permitted ZIP-root exception. GitHub MCP is READ-ONLY — every release
is the owner's extract-and-drag.

*Retired amendment (2026-08-02):* `CHANGELOG.md` ships in the ZIP. The older "never in the ZIP"
rule was a scar from 2026-07-27 (commit 40ed3b6), where a mis-landed ZIP let a rollback `.sql`
overwrite CHANGELOG.md and destroy 700 lines. That rule was retired because its premise was gone:
`changelog-entry.mjs` is a tail-SHA-guarded, prepend-only, idempotent writer, structurally
incapable of the 2026-07-27 failure. **That reasoning still holds and still matters** — it is why
CI's `record-changelog` job can safely own the file today, and why a stub can never clobber a real
entry. Keeping the changelog out of the delivery unit stopped reducing risk and started causing it:
the separate drag got skipped, which is exactly how v0.36–v0.51 decayed into CI stubs.
