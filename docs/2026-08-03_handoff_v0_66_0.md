## §2. What shipped this session

**v0.65.0 — drag-and-drop schedule editor.** `admin-schedule-editor.html`. Drag a match to another
round or court; drop on an occupied slot and the two swap. **It never refuses a move** — a director
knows things the solver does not, and a tool that blocks them is a tool they route around back to
the spreadsheet. The fairness panel reports what each move cost. Keyboard parity throughout (Enter
picks up, arrows move, Escape cancels), because HTML5 drag-and-drop cannot be driven from a
keyboard. Scoring comes from the server using the *same* `poolReport` the generator uses (F-26).

**v0.66.0 — playable brackets** + migration 0037. Detail in `CHANGELOG.md`; the three decisions
worth carrying:

- **Byes to the top seeds, never play-in games** (owner 2026-08-03, verbatim: *"we try to avoid
  pigtails as often as possible with too many people waiting"*).
- **Advancement is recomputed from the scores, not accumulated.** Idempotent, and a corrected score
  fixes the round above it instead of stranding the wrong team there permanently.
- **Bracket games live in `matches`, not a second table**, so score entry, courts and the new
  editor work on them for free. `bracket_round` counts backwards from the final and is
  authoritative; `matches.stage` stays a coarse legacy label clamped at `quarter` because widening
  its CHECK needs a non-additive table rebuild against live scores.

## §3. Two defects found this session that everything reported clean on

**1. Five pages carried stray `</main>` tags, and the count was climbing.** New admin pages are
built by slicing the shell off an existing page. A stray closing tag in the source is inherited
*and incremented*. Browsers discard an unmatched closing tag silently, so every page looked
perfect: member-fields 4, staff-pay 4, tryouts 3, passes 2, and the schedule editor generated this
session 5. Swept, and `page_structure.test.mjs` now scans **every** shipped HTML file. It caught my
own bracket-page generator on its first run.

**2. The cache-buster sweep had only ever touched `.html`.** `admin-nav.js`, `site-nav.js` and
`signup-widget.js` each carry a `?v=` string, and all three had been stale for an unknown number of
releases. Classic failure class 3 — a guard narrower than its subject, reporting clean.

Both were found by running things and reading output, not by reading documents. That remains the
highest-yield activity in this repo.

**Also corrected, honestly:** a test written this session asserted a member got 403 from the
schedule editor. It was passing for the wrong reason at first — the *first* user to verify into an
org with no admin is bootstrapped to admin, so the "member" arrived holding the keys. The test now
burns that bootstrap on a real staff account first.

## §6. Next build

1. **Bracket ergonomics on the day.** The bracket generates, advances and crowns a champion, but
   "Move winners forward" is still a button someone has to press. Calling advance automatically
   after a bracket score is saved is small and removes a step at the exact moment a director is
   busiest. *(Click minimization, owner requirement #19.)*
2. **Third-place and consolation games.** Single elimination sends half the field home after one
   loss. For a club running its own events this is the most-requested next format, and the tree
   already supports it — a third-place match is one extra row fed by the two semi losers.
3. **Roster import** — unblocked the moment a readable sheet arrives. Spec is written.
4. **Google Calendar two-way sync.** `.ics` feeds already work; the owner asked for Gymdesk-like
   behaviour, which means OAuth and write-back. Note that the Google Calendar MCP connector is
   **not authorized** in this environment.
5. Roadmap remainder: M12C rental booking · R-04 payment plans · M18′ roster RSVP ·
   member-experience W1–W10 (`docs/2026-08-03_workorder_member-experience_v1_1.md`, whose §0 lists
