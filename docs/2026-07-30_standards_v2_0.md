## §1. Trust order & session protocol
Repo > live D1 > docs. Verify HEAD version (`grep 'version: "v' worker/src/index.js`), suite
count (`node --test test/*.mjs`), and applied migration vs repo highest BEFORE building.
Measure suite count before AND after — never "projected" (the v0.33.1 lesson).

## §2. Versioning & labels
Date + version in every file header and every filename (docs, SQL). `index.js` carries
NO version in its header, deliberately — `/api/health` is the only honest version source.
The version bump in `index.js` must byte-verify as a one-line diff against the file otherwise
unchanged (F-34 discipline); wiring changes for a new module are reviewed line-by-line.

## §3. Database rules
Additive-only migrations against live D1; numbered `00NN`, applied via Cloudflare MCP before
the deploy that needs them (CI schema-gate fails closed on an unapplied migration). Every
migration ends with its own `schema_migrations` ledger INSERT (version + filename + note —
"a release is not shipped until this row exists", recurring pattern 4). `org_id` + soft-delete
(`deleted_at`) on every table (D-MIG, multi-company day-1). No screening/clearance fields ever
(owner 2026-07-26). Schema facts that bite: `notifications.kind` (not `type`); contacts have
`full_name` (no first/last split); SQLite `=` on TEXT is case-sensitive — match emails with
`lower()` (F-26).

## §4. Worker module pattern
One module = one file exporting `xRoutes(request, env, url, ctx)` + `wireX(helpers)`; helpers
injected from index.js (`json`, `contactForSession`, `audit`, `isStaff`, `requireStaff`; add
`sendEmail`/`escapeHtml` by injection only — never import from a module that imports you).
Every read and write scoped to `ctx.orgId`; no route accepts an org_id from the client (F-11:
fail closed before any route sees ctx). Flood-guard member-facing writers (messages.js
precedent). Fail closed on parse errors (offerExpired precedent). Emails resolve sender via
`senderIdentity` — never a literal company name in source (F-10/F-13).

## §5. Design-skill roster (mandated for any UI work)
`/emil-design-eng` is the base (owner req #13 verbatim) — animation decision framework,
`:active` feedback, ease-out, no animation on high-frequency actions. Plus: `frontend-design`
(structure/aesthetic), `ux-copy` conventions (v0.5.0 precedent — human copy, no jargon,
sentence case). Tokens only: colors/fonts/spacing come from `assets/tokens.css` vars — the
tokens.test.mjs guard ratchets page-level drift. Dark black/gold, light white/navy (owner
req #13). WCAG: bare `:focus-visible` ring via `--focus-ring` (F-35, ≥3:1 contrast), 44px
targets (52px for thumb-critical), `prefers-reduced-motion` respected. Click minimization is
a standing requirement (owner req #19) — count the taps in review.

## §6. Testing & gates
Every release ships tests for what it ships. Guards must include a **negative control that
proves the guard can fail** (mutate the real input and assert failure — tokens.test.mjs
precedent). Prove-it-fails-live for enforcement changes: demonstrate the blocked path actually
blocks before shipping. The four recurring failure classes (library §2) are checked by grep,
not trust: (1) built-but-uncalled — assert index.js actually mounts the new module from source;
(2) decision recorded ≠ decision in force — grep every restatement; (3) a guard narrower than
its subject reports clean — scan the widest set; (4) a skipped gate is no gate — run the full
suite, count it.

### §6.5. Delivery gate greps call sites, not module names (F-15)
An import line must not satisfy the gate. Assert on the dispatch chain (`|| (await xRoutes(`)
and the `wireX(` call, not on the filename appearing anywhere.

## §7. CI
deploy-worker.yml v0.5.0: gate (node --check all modules, full suite, live-D1 read,
schema-gate) → deploy → /api/health parity with cache-buster → record-changelog (idempotent
stub auto-commit, `[skip ci]`). Do not add workflow changes without explicit owner OK (owner
2026-07-30: current method stands). Requires repo Actions "Read and write" permission (O-2).

## §8. Member-facing copy
No literal org email address in member-facing copy (F-40); identity resolves through the org
profile. No exposure of other members' email addresses anywhere member-visible (messages.js
rule). Names shown to members are "First L." unless the member chose public visibility.
Errors are human sentences, not codes.

## §9. Delivery convention
**v2.1 (2026-08-02): the ZIP convention is retired.** The owner authorized direct commit, so the
former rule here — "ONE ZIP mirroring repo paths; CHANGELOG.md never in the ZIP (paste-only);
workflow files are the only permitted ZIP-root exception" — describes a process that no longer
exists. Struck, not amended.

**v2.3 (2026-08-04): the paragraph that stood here is struck too — it was C15.** It described the
v0.36–v0.51 stub workflow: *"commit to `main`, push, then fill the CHANGELOG stub CI wrote… CI
guarantees the entry exists; it does not write it."* There is no stub. Since v0.83.0 the entry goes
**into the release commit before the push**; CI's `record-changelog` step finds it present, its commit
step is **skipped**, and **CI adds no commit at all** — confirmed four times now (v0.83.0, v0.84.0,
v0.85.0, v0.86.0) with `git log main..origin/main` empty after each deploy.

So the fix for C1 replaced one stale sentence with a different stale sentence, in the same section,
and the register did not reopen for two more releases. That is failure class 2 landing on the document
that defines failure class 2, which is why the correction is recorded here rather than quietly applied.

**The hard rule lives in `CLAUDE.md` §2 and is deliberately not restated here.** A second divergent
copy is what kept this section wrong three times over. The one-line version, for orientation only:
preflight CLEAR → changelog entry written into the commit → commit → push, and that is the whole
release.

```bash
node worker/scripts/changelog-entry.mjs --version vX.Y.Z --date YYYY-MM-DD --body-file entry.md
node worker/scripts/changelog-entry.mjs --check --version vX.Y.Z   # --version is REQUIRED
```

## §11. Page and asset structure

**When a page gets its own script.** A page gets `web/assets/<page>.js` when it **fetches from the
API or holds state**. A pure-markup page keeps its script inline. That is what the tree already
does — `home.js`, `member.js`, `profile.js` and `widget.js` exist because those four pages do both;
the static pages do not — but no rule said so, and an undocumented convention drifts the moment two
people disagree about a borderline page. Borderline cases resolve toward a separate file: a page
that grows a second `fetch` has already crossed the line.

**Shared scripts may not depend on one page's styles.** `admin-nav.js` and `site-nav.js` render into
every page, so anything they emit must be styled by `app.css`/`admin.css`, never by a single page's
`<style>` block. `button_vocabulary.test.mjs` enforces the button half of this: a shared script that
emits a `.btn` modifier with no base is flagged with no page-level exemption available to it.

**Numbered SQL lives in `db/migrations/`, and nowhere else.** Migrations 0004–0007 sat loose at `db/`
root until v0.83.0 while `schema_gate.test.mjs` scanned only `db/migrations/` — four applied
migrations no gate had ever covered, and a `schema_migrations` ledger whose `filename` column read
"(see db/migrations/)" while pointing at a directory they were not in. A file's location is part of
whether a guard can see it.

## §10. Document/templating rules
No hardcoded company names or short forms in document bodies — tokens resolve from the org
profile at publish (F-8, D-DOC-5/6). Square brackets are invisible to the `{{…}}` validator
(F-1) — token syntax is `{{TOKEN}}` only. Signatures pin `version_id` + `body_sha` forever
(D-DOC-8). Waiver system is CLOSED to further work (owner 2026-07-26).
