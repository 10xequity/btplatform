## §3. The pattern, and the sharpest lesson

**Eleven defects found, every one reporting clean beforehand, all the same shape: the thing existed and
the path to reaching it did not.** The rail went dark on the page where a tournament is built. The test
fixture could not reach the feature it existed to test. Captain scoring was pool-only. The QR had never
worked and said so only on the screen where it was needed. Five pages had accumulated stray `</main>`
tags. The buster sweep had never covered `.js`. Pool membership was unwritable before a schedule
existed. The divisions engine shipped with no screen.

**Five defects in code written this same session**, each caught by a test rather than by reading: a team
named "Spike Lee's" broke the seed SQL; the QR generator polynomial was built reversed; QR format bits
were split 8+7 instead of 7+8; the bracket trim would have dropped fourteen teams from a 22-team
division; and a hardcoded test date turned a green suite red on a calendar boundary with no code change
at all.

**THE SHARPEST LESSON, and it is now in §7: a negative control aimed at the wrong region is
indistinguishable from a working one.** Three of this session's controls passed while proving nothing —
one corrupted error-correction parity the decoder ignores, one corrupted a mode indicator that does not
change the output, and one only ever produced the single proposal kind its assertion happened to read.
Each was found only by asking "what exactly did that mutation touch?"

Recorded 2026-08-03:
- **Pool play never offers fewer than 8 games.** "if we do 6 on 2, with 4 games, we would double the
  number of games to equal 8."
- **Pools aim for 6–11 teams**, larger where possible. Mostly grass; indoors is court-limited.
- **Rebalancing is propose-then-approve, never automatic.**
- **Top division holds at 8** — trim the 9th/10th when they have played 8+ games; a large overflow is a
  second bracket, not a mass drop.
- **A 22-team division becomes 8 / 8 / 6** when the trailing six are competitive; 8 / 4 / 2 when the
  bottom two are adrift.
- **Bracket seeding is a starting point.** Any slot takes any team; the admin decides after reviewing
  scores; teams forfeit and quit, so flexibility beats correctness here.
- **Two views:** admin creates, a public display view shows. No login on the display.
- **Captains on every tile**, including live scores — abbreviated on public surfaces per standards §8.
- **QR: stop work.** "we can simply use a web link and use a website to encode the qr later."
- **KOTC partner repeats are allowed**, ideally avoided, never a fixed constraint.
