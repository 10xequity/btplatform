### The finding worth carrying: a list crosses the wire as an ARRAY

`parseList` JSON.parses a string **before** it falls back to splitting on commas. So the single
value `"16"` parses as the *number* 16, fails `Array.isArray`, and comes back as `[]`. A form that
posted its comma text box raw would therefore **silently delete the age group the user just typed**
— but only for the all-digits case. `"14U, 16U"` works perfectly, which is precisely why that bug
would survive review, ship, and be reported months later as "it sometimes loses the age group".

The client splits the box itself and posts an array. **The guard proves the trap against the real
validator** (`normalizeCard({age_groups:"16"})` → `[]`, `["16"]` → `["16"]`) rather than describing
it in a comment, so the assertion explains *why* the client rule exists instead of just pinning it.
NC-1 mutates the real shipped client to post the raw string and proves the guard catches it.

**The general shape: a server helper that is permissive about input types has a narrow input that
behaves differently from the wide one, and the wide one is what everybody tests with.** Worth
checking the next time a client hands a list to a route.

### The rest of the unit

- **The client does no unit arithmetic.** Height is stored metric and rendered imperial **by the
  server** (`cmToImperial`). A feet-and-inches box here would have to round-trip, and 5'11" is a
  *range* of centimetres rather than one, so every save of an unrelated field would quietly rewrite
  a stored height that was never wrong. The field asks for centimetres, says so in its own label,
  and shows what is on file today in the server's words. A5 pins the absence of `2.54` and `/12`.
- **Both `#tList` listeners are delegated and attached once, at boot.** That node has its innerHTML
  replaced on every render but is never itself recreated. §-1c **D-6** not inherited a second time,
  and the assertion is **positional** (every `$("tList").addEventListener` index at or after the
  boot block), so a rename cannot satisfy it. NC-2 inserts a real listener into `render()`.
- **A re-render cannot discard a half-typed correction.** Typing in "Find a player" rebuilds every
  card; the form's live values are kept in a draft and redrawn, and **focus is put back on the
  control the user pressed** rather than falling to `<body>` — a keyboard bug the disclosure would
  have shipped with, since `render()` replaces the very button that was just activated.
- **The error appears in the form.** `fail()` would replace the whole list with a dead end and take
  the half-typed correction with it. An unrecognised position is dropped by the server rather than
  refused, and the form offers exactly the six it accepts.

`tryouts_card.test.mjs` **(+12, 1338 → 1350)**, three negative controls each mutating the real
shipped client, plus the comment stripper controlled in both directions.
