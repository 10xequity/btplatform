### The invariant with no visible symptom

`kotc_games` stores the four players **on the game row**, which is what lets the leaderboard be derived
from games alone with no stored counter to disagree with. The cost: a re-seat *could* retroactively change
who played a game that is already scored, and because the leaderboard is derived, it would **silently
restate the evening**. Nothing on the screen would look wrong. Nothing would throw.

So a game with both scores in is **finished and never touched**; only unplayed rows are re-paired. The
test **mutates the real input** — same session, same move, same game row, scores cleared — and proves the
same move *does* re-pair it. Without that control, "the finished game is unchanged" would pass for the
boring reason that the route never re-pairs anything.

**"Never refuses" is tested by exhausting the board, not sampling it:** one player dragged to every seat
that exists, in turn. *Never* is a claim about the cases nobody thought of.

### Two traps worth carrying forward

**`rotation()` throws for any net size that is not 4 or 5 — and `dispatch` treats a throw as a DECLINE.**
An unguarded call would have turned a drag into a **silent 404**, the route looking *absent* rather than
broken. A short net now warns and is left alone (brackets.js precedent). Anything calling into `kotc.js`
from a route needs this check.

**A guard's own comments tripped it twice.** The check for "nothing animates from `scale(0)`" matched the
comment saying nothing animates from `scale(0)`; the check for "no roster on a public surface" matched the
comment saying there is no roster. v0.85.0 hit the identical thing on `kotc.html`, and the design hook hit
it a fourth time on `admin-nav.js` — a comment describing an `<img>` flagged as a broken image. That is
four instances in two sessions, which makes it a shape: **check the set that ships BEHAVIOUR.** A comment
ships bytes, not behaviour, and a guard that cannot tell the difference punishes the explanation and
rewards silence. The fix is a comment-stripping corpus **with its own negative control**, so it cannot
become a quiet way of switching the check off.

`asset_versions.test.mjs` had asserted since v0.41.0 that the busters were **one** value and never that

**That is the lesson, and it is now in the standing-rules table:** widening what a guard SCANS and
fixing what it ASSERTS are two different repairs, and doing the first can make the second look done.

Two halves, shipped together:

1. **`worker/scripts/sweep-buster.mjs`.** Corpus discovered by a filesystem walk (the `sync-rail.mjs`
   shape) with the **repo root first** in the directory list, because that is the entry forgotten twice.
   Shrinking-corpus floor: it refuses to sweep fewer than 40 files.
   **Its check uses the GIT INDEX (`git ls-files`) — a different source of truth, not a second phrasing
   of the same walk.** The two sets are deliberately asymmetric: a *tracked* file in a directory the walk
   never visits is C13/C14 caught mechanically; an *untracked* new page is a page about to ship stale.
   Disagreement is the finding and the script exits 2 rather than picking a winner. It prints the count
   and says **"RECORD THIS COUNT in the handoff"**, because a written-down number from the previous
   release is the only reason C14 was ever found.
2. **`asset_versions.test.mjs` v1.3** — `assert.equal(only, versionFromIndex(index.js))`. The corpus
   stays this guard's own (three URL roots, `readdirSync`) and shares nothing with the script's walk;
   only the version *parser* is shared, deliberately, because a second copy of that regex is the C1/C15
   shape.

Both ship negative controls that **mutate real input**. The script's reconstructs the historical defect:
the real corpus with the repo root dropped, against the real git index and the real `404.html`, asserting
the blind spot is caught. The guard's reconstructs v0.55.0 — a bumped version with unswept busters, a
state the old assertion passed.

Four answers given 2026-08-04, all NEW, all settled:

1. **POINTS CAP IS PER-SESSION, THE DIRECTOR SETS IT.** `NULL` = no cap; `23` = games to 21, cap 23 —
   which is what the men's tournament actually played. **This SUPERSEDES the old "first to 21, no cap"**
   in this section, in `spec_kotc` §6 Q3, and in migration `0040`'s note, which deliberately omitted a
   cap column. It is **not a documentation fix**: `solveNet`'s closed form rests on a shape rule that a
   game ends only `21 to ≤19` or `n to n−2`. **A cap of 23 permits 23–22, a one-point margin**, so the
   solver needs a third case and its 4000-round randomised verification re-run. Migration + solver, and
   **the migration must be applied via Cloudflare MCP by a human before the push.**
2. **NET LABELS: AUTO-ASSIGNED BY DEFAULT, EDITABLE BY THE DIRECTOR.** Division (`AA`/`A`/`BB`) and role
   (`Champ`/`Contender`), as on the real sheet — *"Net 3 (A) Champ"*. Owner: *"we add row labels by
   default but allow us to edit it."* Needs a migration.
3. **WHEN A NET LOSES PLAYERS, ITS PLAYERS ARE REDISTRIBUTED UP AND DOWN TO KEEP NETS AT FOUR, AND THE
   NET NUMBER IS RETIRED — NOT RENUMBERED.** Owner, verbatim: *"we had a net but people could not come
   so we split the players from that up and down to best fit the 4 into the system."* This is why the
   real round 3 ran on nets **1, 3, 4, 5, 6** with no Net 2. `nextRound` moves by `net_no ± 1` and
   therefore **refuses outright on non-contiguous nets** — measured, fails closed with a human sentence,
   nobody is lost, but auto-advance would have refused on their actual tournament.
4. **A CONTENDER NET MAY BE DELIBERATELY REMOVED** *"to give more players chances to win"* — dropping a
   net is a director's call, not an error state.

**And the movement model itself is confirmed, hard:** ranking all 24 by wins-then-diff and cutting into
