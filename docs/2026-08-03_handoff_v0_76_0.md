## §3. The review pass, and what it says about the previous session

Task A was a fresh-eyes review of v0.65.0–v0.74.0 on the standing suspicion that a session finding five
defects in its own same-day code has not found the sixth. **It found six, four of them in code no test
touched.** Every one was proved against the real router before it was fixed — eight probes, not eight
opinions.

| Defect | Why it hid |
|---|---|
| The manual bracket override was silently reverted **in the owner's primary use case** | The warning was wired to the rarer branch: it fired when the feeding game was *unplayed*, and stayed silent when it had *already been won* — which is a team winning and then going home, the whole reason the route exists. Two tests covered the route's warning; both passed throughout. |
| Bracket generation **double-booked courts**, two ways | A and BB each numbered their own courts from 1; and any round with more games than courts did it to itself. Invisible in the database, drawn happily by the court grid. |
| A seed list naming the same team twice drew it into **both semi-finals** | The length check that catches bad input passes duplicates. |
| Two divisions at the same rank returned **`500 Server error` and a half-written layout** | The route validated court overlaps carefully and never looked at the column beside them. No transaction. |
| A team could be filed under **another event's division** | Both writes were org- and event-scoped on the *team*. The division never had to be. |
| Saving the pool board could **fail the whole save on live D1** | An empty pool is hard-deleted, but the pointer-clearing loop walks the live roster, so a withdrawn team kept pointing at the row about to vanish. |

**THE SHARPEST FINDING, AND IT IS ABOUT THE CHANGELOG ITSELF.** v0.74.0's entry states: *"Corrected the
live board's own header comment, which claimed 'no player names anywhere' and had stopped being true
the moment this shipped."* **It was not corrected.** `git show 89d2490 -- worker/src/live.js` shows a
**new** comment added above `publicTeam` and the stale header line untouched. A comment was written
*near* the problem and mistaken for a fix.

That is failure class 2 in its purest form, landing on the one document the project treats as history:
**a CHANGELOG line saying a thing was fixed is not evidence the thing was fixed.** The only evidence is
the file. Registered as **C9** in `docs/INDEX.md`.

Also found: the QR alignment-coordinate table had a **middle** value (versions 7–10) asserted by
nothing — and the round-trip test *imports* that table, so a wrong number would be wrong identically on
both sides and still decode. A mistyped centre there produces a QR that renders perfectly and will not
scan. Now derived from the ISO 18004 rule; all ten rows verified, none were wrong.

**Verified correct, so nobody re-reviews it:** the whole QR spec layer (tables against both the
internal identity and the ISO level-M figures, GF(256), the generator polynomial hand-checked at n=2,
both BCH codes hand-verified against the spec strings, all eight masks, the zigzag walk, all four
penalty rules, the 7+8 format split), `buildTree`'s empty-pair invariant (genuinely provable),
`bestSplit` at every size including 22 → 8/8/6, and `abbreviate`. **And the three negative controls
v0.74.0 flagged as proving nothing were genuinely repaired, not merely annotated** — confirmed in
source, not taken on trust.
